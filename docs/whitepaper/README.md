# 데이터 백서 — 설계 (세션559)

> **무엇을 어디서 받아, 얼마나 쌓고, 어떻게 가공해, 어떤 이름으로 보여주는가**를 한 장에 모은다.
> 손으로 쓴 문서는 반드시 낡으므로 **기계가 뽑는 표 + 사람이 쓰는 판단** 두 층으로 만든다.

## 왜 필요한가 — 세션559가 증명한 것

하루에 세 건의 결함을 찾았는데 **전부 같은 종류**였다:

| 무엇 | 사람어(화면) | 기계어(DB/코드) | 실제 내용물 | 문제 |
|---|---|---|---|---|
| 미분양 | "미분양 42세대" | `apartments.unsold` | **오늘 네이버 매물 42건** | 1,157곳(58%)이 매물 수. 81곳은 세대수 초과(최대 1,800%) |
| 대기질 | "대기: 보통" | `air_quality.grade` | **오늘 한 시점** 실시간 측정 | 내일 재면 점수가 달라짐 |
| 적정가 | "적정가" | `trade_stats.nearby_median` | 실거래 **또는 호가**(구 거래 3건 미만 시) | 출처를 기록조차 안 함(`medianSource` 계산 후 버림) |

**공통 뿌리: 이름과 내용물이 다른데 어디에도 안 적혀 있었다.**

그래서 백서의 핵심 칸은 **"실제 내용물"**이다. 이 칸이 있었으면 "미분양 = 오늘 매물 수"가 첫날 드러났다.

## 구조 — 두 층

### 1층: 기계가 뽑는 표 (`npm run whitepaper`)

코드·DB에서 **매번 새로 추출**한다. 낡을 수가 없다.

추출 가능한 재료 (2026-09-22 실측):
- 수집기 **61개** (`scripts/collectors/*.mjs`)
- VIEW 컬럼 **124개** (`AS "camelCase"` — 기계어↔중간이름 대응)
- 화면 항목 **150개** (`fieldMeta.ts` — 사람어 label·단위·표시 형식)
- 점수 가중치 (`scoringTiers.ts` 의 `*_WEIGHTS` 상수)
- 수집 주기 (`.github/workflows/*.yml` cron + `kosis-local-runner.mjs` DAY_TABLE)
- 채움률·최신 갱신 시각 (DB 실측)

**세 이름이 다 다를 수 있다** — 이게 이 표의 존재 이유다:

```
사람어(화면)      기계어(DB)              코드 변수         실제 내용물
"적정가"      ←   trade_stats.nearby_median  ←  apt.nearbyMedian  ←  실거래 중위 or 호가 중위
"미분양 세대"  ←   apartments.unsold          ←  apt.unsold        ←  KOSIS 구단위 비례배분
```

### 2층: 사람이 쓰는 판단

기계가 못 뽑는 것 — **"이 값이 사실 무엇인가"**와 **"믿을 만한가"**:

| 칸 | 예시 | 왜 사람이 써야 하나 |
|---|---|---|
| 실제 내용물 | "구 단위 통계를 세대수 비례로 나눈 **추정치**" | 코드만 봐선 의도를 모른다 |
| 시간 성격 | 🔴 매일 바뀜 / 🟡 월 단위 / 🟢 사실상 고정 | 점수에 쓸 수 있는지 가르는 기준 |
| 신뢰도 | "단지별 실측 아님 — 같은 구는 같은 값" | 손님에게 밝혀야 할 한계 |
| 주의사항 | "폴백 경로가 있고 그때는 출처가 바뀐다" | 오늘 세 건이 전부 이 칸에 해당 |

## 시간 성격 — 점수 반영 가능 여부의 기준

세션559 전수조사에서 확립한 분류:

- 🔴 **날/주 단위로 바뀜** → 점수에 쓰면 안 된다. 아파트는 오래 살 집이다
- 🟡 **월/분기** → 쓸 수 있으나 "언제 기준"인지 화면에 밝힌다
- 🟢 **년 단위 이하 또는 고정** → 안전 (위치·면적·준공년도 등)

## 만드는 순서

1. **1층 추출 스크립트** — 61개 수집기 × 124 VIEW 컬럼 × 145 화면 항목을 엮는다
2. **2층 사람 칸** — 우선 🔴·🟡 지표부터 채운다(전체를 한 번에 채우려다 못 끝내는 것보다 낫다)
3. **CI 연결** — 표와 코드가 어긋나면 실패하게 (선택)

## 원칙

- **추측 금지** — 채울 수 없는 칸은 "미확인"으로 남긴다. 그럴듯하게 채우면 백서가 거짓말을 시작한다
- **낡은 칸은 낡았다고 표시** — 2층은 사람이 쓰므로 `확인일` 칸을 둔다
- **이 문서 자체도 백서의 일부** — 설계가 바뀌면 여기부터 고친다

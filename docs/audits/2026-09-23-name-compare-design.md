## 한눈에 (사장님용)

좌표를 고치는 도구는 카카오 지도에서 단지를 **이름으로** 찾는다. 지금은 두 가지를 틀린다.

1. **같은 단지를 못 알아본다** — `중흥S-클래스` ↔ `중흥S클래스`처럼 줄표 하나, 또는 우리 이름에만 있는 `3차` 때문에 점수가 기준에 못 미친다.
2. **다른 단지를 같다고 본다** — `6차` ↔ `7차`, `C3블록` ↔ `D3블록`, `루체Ⅰ` ↔ `루체Ⅱ`처럼 번호만 다른 옆 단지가 0.92~0.94로 "맞음"을 통과한다.

설계안: **표기 차이(줄표·기호·전각·로마숫자)는 점수를 매길 때만 무시하고, 번호(차수·단지·블록)는 서로 맞아야 하는 값으로 다룬다.**
모의 계산 — 사장님이 어제 승인한 42곳 중 4곳을 도구가 스스로 고르게 되고, 청약홈 이름 약 970곳 표본에서 옆 번호를 잘못 고르던 8건이 사라지며, 1km 넘게 떨어진 새 오선택은 0건이다.
자동으로 옮기는 범위는 늘지 않는다(금강은 점수가 여전히 0.85 미만, 나머지는 3km 초과라 기존 안전장치가 "보고만"으로 둔다) — **사람이 볼 목록이 정확해지는 것**이 1차 효과다.

### 3. 선택지

- **① 점수 계산 안에서만 표기 정규화** — 새 `normalizeForScore`: 로마숫자 Ⅰ~Ⅹ를 **먼저** 숫자로 → NFKC → 소문자 → 줄표 삭제(단 숫자-숫자 사이는 유지: `D1-2`≠`D12`) → `·.,&'"/` 삭제. K `pickKakaoCandidate` 와 F `analyzeKakaoDocs` 가 같은 함수를 쓴다. 6/7차·C3/D3 구멍은 남는다. ⚠️ 로마숫자 선매핑 없이 NFKC 만 쓰면 `루체I` 가 `루체II` 의 부분문자열이 되어 오히려 강함이 된다.
- **② 공용 `cleanName` 에 넣기 — 기각.** 카카오에 보내는 질의 자체가 세 경로에서 바뀌고, `stripDevAreaPrefix` 56행 표·`hasDistinctProjects`·`coreName` 이 연쇄로 바뀌어 전/후 비교가 불가능하다. N차까지 지우면 6차/7차가 sim 1.00(세션542 결정과 충돌).
- **③ ① + "번호는 맞아야 하는 번호" (추천·채택)** — 번호를 종류별로 뽑아 같은 종류끼리만 비교: 차수(`N차`+로마숫자) · 단지(`N단지`, 단 `…마을N단지` 제외) · 블록(원본의 `N BL·블록·블럭` + 기존 `blockConflict`). 둘 다 번호가 있는데 겹치지 않으면 **후보 제외**(결정 2). 양쪽 차수가 같으면 빼고 비교(뺀 질의 8자 이상일 때만, 강함 가능). 한쪽에만 있으면 빼고 비교하되 **약함 자격까지만**(결정 1 — 좌표 채우기는 gu 게이트를 지나야 채택). 순위·보고 sim·`APPLY_MIN_SIM` 에는 **차수를 빼지 않은 값**을 쓴다(뺀 값으로 순위를 매기면 `춘천 레이크시티 2차` 가 차수 없는 옆 단지 113m 를 고르는 것을 모의로 확인). 유일성 개수는 제외 전 전체 문서에서 센다.

대조군 (지금 → ③): 6차↔7차 0.94 통과 → 제외 · AB23↔AB22/AA23 구제 가능 → 제외 · C3↔D3 0.92 → 제외 · 루체Ⅰ↔Ⅱ 0.93 강함 → 제외 · 양주역중흥S-클래스↔수원 `중흥S클래스` 0.75→0.80(약함, 시군구 게이트가 계속 막음) · 힐스테이트 5자 null 유지 · 검단 AB19 `호반써밋`↔`호반써밋1차` null 유지(8자 조건 없으면 0.73 강함으로 뽑힘).

### 4. 파이프라인별 예상 변화 (③)

- 정정 도구 F: 새로 잡히는 K 는 보고용 등급(weak/far)에만. 번호 충돌로 K 가 빠진 행은 `ok` → 다른 등급으로 바뀔 수 있으니 전부 확인. 표기 정규화만으로 sim 이 0.85 를 넘어 자동 반영 등급에 새로 들어갈 수 있다(표본: 두산위브&수자인 0.84→0.87) — 전/후 비교에서 한 곳씩 확인. 제외된 후보는 kCands 에 `qualified:false` + 사유로 남긴다. 사람 승인(30m 대조) 경로는 그대로.
- 좌표 채우기 G·D: 표기만 다른 새 단지는 좌표를 받는다. 옆 번호 이름만 있는 새 단지는 정직한 null(미확정 증가). D 의 좌표 중복 판정(결정 4)을 더 자주 거친다.
- 바꾸지 않는 것: `cleanName`, 카카오 질의, `stringSimilarity`, `normName`, C 매칭, `coreName`, 문턱 상수(결정 3 은 별도 설계 필요 — 아래).

### 5. 결정 3 (짧은 이름) 을 넣을 때 추가로 정할 것

`아파트` 꼬리를 무조건 떼는 방식은 **권하지 않는다** — 같은 표본에서 남의 단지를 고르는 오탐 8건이 새로 생기고 그중 2건이 강함이었다(예: 동탄역 롯데캐슬 → 동탄2롯데캐슬, 4.6km). 넣는다면 "짧은 이름 + 카카오 이름이 우리 이름 + `아파트` 와 **정확히 같을 때만**" 처럼 좁은 조건으로, 전/후 비교에서 새로 자동 반영 등급에 들어오는 행을 한 곳씩 확인한다.

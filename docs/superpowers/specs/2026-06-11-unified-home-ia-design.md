> 정보를 하나도 누락시키지 않고 한군데 어울리게." 시각 컴패니언 3라운드(IA 3안 → C안 확정 3클릭
> → 지도클릭 동작 → 전문가 옵션 1)로 결정 완료.

## 1. 새 IA 구조

```
홈(신설, 기본 탭)                    ← 위젯판. 모든 화면의 허브
├── 🗺 지도 위젯      → 펼치기 = 기존 지도 탭 (MapView 전체)
├── 📅 곧분양 위젯    → 펼치기 = 기존 /upcoming 페이지 전체
├── ⭐ 추천 TOP 위젯  → "전체 목록" = 기존 목록 탭
├── 📊 시장 요약 위젯 (이미 로드된 데이터 집계만)
├── 🔬 점수 분해 위젯      (전문가 로그인 시) → "전체" = 기존 ExpertDashboard
└── ✅ 데이터 완성도 위젯  (전문가 로그인 시) → "138필드 표" = 기존 ExpertDashboard

기존 탭 전부 보존: list / map / upcoming / expert / expertConsults / consult / info / admin
```

### 핵심 인터랙션 (D2 확정)
1. 홈 미니지도 핀 클릭 → 지도 위에 단지 요약 카드(말풍선) = `SelectedAptCard` 재사용
2. (전문가 로그인 시) 같은 클릭으로 점수분해·완성도 위젯도 **그 단지 기준으로 동시 갱신**
3. 카드 "상세 보기" → 기존 `DetailModal` (6섹션 13블록) 그대로
4. 모바일: 핀 클릭 → 하단에서 카드 시트 (기존 지도 탭과 동일 패턴)

### 네비게이션 (D4 확정)
| 위치 | 변경 전 | 변경 후 |
|---|---|---|
| 모바일 하단 (소비자) | 목록·지도·📅·비교·상담·정보 (6) | **홈**·목록·지도·📅곧분양·정보 (5) |
| 모바일 하단 (전문가) | 대시보드·상담목록·소비자뷰·지도·로그아웃 (5) | **홈**·대시보드·상담목록·소비자뷰·지도·로그아웃 (6) — 전문가는 소수 파워유저, 조정 가능 |
| 데스크톱 상단 (소비자) | 목록·지도·곧분양N·비교·상담·정보 | **홈**·목록·지도·곧분양N·비교·상담·정보 (7, 자리 충분) |
| 데스크톱 상단 (전문가) | 대시보드·상담목록·소비자뷰·지도·곧분양 | **홈**·대시보드·상담목록·소비자뷰·지도·곧분양 |

- 모바일에서 빠진 **비교** = 목록 화면 내 플로팅/상단 버튼으로 이동 (showComp 토글 기능 그대로)
- 모바일에서 빠진 **상담** = 정보 페이지 안 진입 + DetailModal 상담 버튼(기존 onConsult) 유지
- 기본 탭: 신규 방문 `tab` 초기값 `list` → `home`. `/upcoming` URL 직진입은 현행 유지

## 2. 컴포넌트 설계 (재사용 최우선 — 신규 최소)

| 컴포넌트 | 신규/재사용 | 내용 |
|---|---|---|
| `src/components/home/HomePage.tsx` | **신규** | 위젯 그리드 컨테이너. 데스크톱 2~3열 grid / 모바일 1열 stack (auto-fit minmax 패턴 — 세션387 답습). `selectedApt` 상태 보유 |
| 지도 위젯 | **재사용** | `MapView`(이미 `filtered`+`onDetail` props, lazy+memo)를 높이 제한 컨테이너로 임베드. `SelectedAptCard` 그대로 동작. "펼치기 ↗" = `setTab("map")` |
| 곧분양 위젯 | **재사용+소형 신규** | App.tsx L70-77이 헤더 라벨용으로 이미 fetch하는 `/api/upcoming` 응답을 위젯과 공유(state lift, 중복 fetch 0). 위젯 = 이번주 N건 + D-day 임박 3건 리스트. "펼치기" = `setTab("upcoming")` |
| 추천 TOP 위젯 | **재사용** | `useDataPipeline` 산출(목록과 동일 점수·프로필) 상위 3. 카드 표시는 AptCard 축약 or 텍스트 행. "전체 목록 →" = `setTab("list")` |
| 시장 요약 위젯 | **신규(집계만)** | **이미 로드된 데이터만 클라이언트 집계** (전체 단지 수, 곧분양 수, 미분양률 중위값 등). 새 API·수집기 0. 지표 목록은 구현 시 가진 필드 실측 후 확정 |
| 점수 분해 위젯 | **재사용** | `ExpertScoreBreakdown`(standalone memo)을 selectedApt 1단지 모드로 임베드. 미선택 시 "지도에서 단지를 선택하세요" 빈 상태 |
| 완성도 위젯 | **재사용** | `ExpertDataCompleteness` + `computeCompleteness`(src/lib/completeness.ts, 세션380 공유함수) 재사용. "138필드 표 전체 →" = `setTab("expert")` |
| `BottomNav` / `HeaderSection` | **수정** | navItems에 홈 추가 + D4 5탭 재배열 (두 파일 모두 하드코딩 배열) |
| `App.tsx` | **수정** | `tab === "home"` 분기 + 기본값 변경 + upcoming 응답 state lift |
| `featureFlags.ts` | **수정** | `isFeatureHome()` 추가 (isFeatureUpcoming 패턴 답습) — OFF면 현행 IA 그대로 = 안전 롤백 |

## 3. 데이터 흐름 (새 fetch 0)

```
useDataPipeline (기존) ──→ filtered/scored ──→ 홈: 지도 위젯·추천 TOP·시장 집계
/api/upcoming (기존, App L70-77) ──→ state lift ──→ 헤더 라벨 + 곧분양 위젯 공유
selectedApt (홈 로컬 상태) ──→ SelectedAptCard + 전문가 위젯 2종 동기 갱신
로그인 상태 (기존 expert) ──→ 전문가 위젯 2종 표시 여부
```

- **새 API·수집기·테이블 없음.** 홈은 이미 흐르는 데이터의 재배치다.
- 번들: MapView(Kakao SDK)가 첫 화면에 옴 → 위젯 전부 lazy + Suspense 스켈레톤 (기존 lazy 패턴 답습). 성능 회귀 시 미니지도만 "탭하면 로드" 폴백.

## 5. 빈 상태 / 에러 처리

- 위젯 단위 독립: 한 위젯 실패가 홈 전체를 깨지 않음 (위젯별 ErrorBoundary 또는 상태 분기)
- 곧분양 API 실패 → 위젯에 "불러오기 실패 · 재시도" (UpcomingPage 5상태 패턴 답습)
- 전문가 위젯 미선택 시 → "지도에서 단지를 선택하세요" 빈 상태
- featureFlag OFF → 홈 탭 자체 미노출, 현행 IA 그대로 (UpcomingPage 가드 패턴 답습)

# 실행 플랜 — 수집기 → 분별력 → 재배치 → 시각화 (2026-08-11)

> 사장님이 정한 순서다. **이 순서를 바꾸지 않는다.**
>
> ① 수집기 고치고 → ② 데이터 각각 재정비해서 분별력 있게 → ③ 재분류해서 카드에 재배치 → ④ 각각 시각화
>
> 왜 이 순서인가: 데이터가 틀린 채로 분별력을 손보면 틀린 기준이 박히고, 분별력이 없는 채로
> 재배치하면 의미 없는 값을 예쁘게 늘어놓게 되고, 배치가 안 정해진 채 시각화하면 다시 그린다.
> **앞 단계를 건너뛰면 뒷 단계를 두 번 하게 된다.**

수치는 전부 **2026-08-10 운영 API 스냅샷**(n=1,646, 미리 계산된 점수 보유 1,597곳) 실측이다.

### 2-4 — 프로필 맞춤이 사실상 작동하지 않는다

`CLAUDE.md` 첫 줄이 "같은 단지여도 프로필마다 다른 점수"라고 선언하는데, 실측은 그렇지 않다:

| 프로필 쌍 | 순위 상관 | 상위 10곳 겹침 |
|---|---|---|
| 실거주 ↔ **자녀교육** | **0.987** | **8/10** |
| 실거주 ↔ 신혼부부 | 0.955 | **9/10** |
| 실거주 ↔ 은퇴 | 0.985 | 6/10 |
| 자녀교육 ↔ 은퇴 | 0.970 | 6/10 |
| 투자 ↔ 은퇴 | 0.788 | 1/10 |

**5개 프로필이 사실상 "투자" vs "나머지 4개" 두 갈래.**

**원인**: 프로필이 **카테고리 6개의 비중만** 바꾼다. 자녀교육(입지 45%)과 실거주(입지 40%)의 차이는
5%p 뿐이고, 입지를 올려도 학군만 오르는 게 아니라 지하철·병원·마트까지 통째로 오른다.
**자녀교육 손님이 원하는 학군은 입지 안에 묻힌 서브지표라 프로필이 건드릴 수 없다.**

**처방 방향(사장님 승인 필요)**: 프로필에 **서브지표 보정치**를 둔다. 예 —
자녀교육 = 입지 45% + `학군 ×1.5 · 초등도보 ×1.5` / 은퇴 = 입지 35% + `병원 ×1.5 · 공원 ×1.3 · 소음 ×1.3`.
카테고리 가중치는 그대로 두고 그 안에서 서브 비중만 손보는 방식이라 기존 구조를 덜 흔든다.

**② 완료 판정**: 죽은 지표 0개 · 몰림 80%+ 지표 0개 · 프로필 쌍 순위 상관 **0.95 미만** ·
상위 10곳 겹침 **7 이하**.

## ④ 각각의 데이터 시각화

D4 가 정한 5형태 중 **지금까지 새로 만든 건 계단 칸 하나뿐**이다. 막대·눈금 점은 세션 487·505 자산이고,
**판정 칩과 "전국 위치 + 실값 병기"는 코드에 아예 없다.**

| 값의 성격 | 형태 | 대상 |
|---|---|---|
| 범주 (복도식·난방·향·평면) | **판정 칩** — 좋다/보통/주의를 색과 한 마디로 | 건물 정보 4행 |
| 숫자 (용적률·건폐율) | **눈금 막대** — 구간 위 위치 + 실값 병기 | 건물 정보 2행 |
| 거리 (IC·KTX) | 눈금 점 (기존 자산 재사용) | 교통 2행 |
| 개수 (버스 노선·정류장) | 막대 | 교통 2행 |
| 지역 통계 7행 | 지역 대비 막대 (기존 `DeviationRow` 재사용) | 지역 통계 서랍 |

⚠️ **값을 숨기지 않는다.** 그림은 판단을 돕는 것이지 숫자를 대신하는 게 아니다 — 실값을 옆에 병기한다.

**④ 완료 판정**: 손님 화면의 라벨:값 격자가 **0행**. 라이브 화면 육안 확인.

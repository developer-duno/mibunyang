## 0. 사장님 질문에 먼저 답한다 — "예전 거 그대로 할 거면 이걸 왜 하는데"

**리뉴얼은 실제로 일어났다.** 손님 화면이 이렇게 달라졌고, 전부 코드로 확인했다:

- 규제지역 목록이 **거짓에서 현행으로** 바뀌었다 (옛 목록은 이미 효력이 끝난 지정을 보여주고 있었다). 대출 한도 계산(LTV)도 10·15 대책 규칙으로.
- 접이식 서랍(아코디언)이 **44개 → 21개**. 종합·시세·분양·금융 네 탭은 **0개**.
- 없던 것이 생겼다: 두 출처 대조표 · 지역 통계 서랍 · 종합/입지 판정 한 줄 · 건물 정보 카드 · 시공사 카드 · 교통 카드 · 층별가 계단 · 청약 위치 막대 실값 병기 · 점수 "세부 N개".
- 종합 탭 핵심지표가 4행 → 2행으로 줄고, 카테고리 미니카드가 위로 올라와 첫 화면 안에 들어왔다.

**그런데 사장님이 화난 지점도 실재한다.** 정확히 세 가지다:

| 화난 지점 | 실제로 무슨 일이 있었나 |
|---|---|
| **간판 문장이 안 지켜졌다** | D4 의 대표 문장은 "라벨:값 격자 폐지"인데, 신설 카드 3종의 **속이 옛 격자와 글자 단위로 같다**. 코드 주석이 스스로 "byte-identical(바이트 단위로 동일)"이라고 적어 뒀다. 격자를 **없앤 게 아니라 상자 안으로 옮기고 뚜껑에 새 이름표를 붙인 것**이다. |
| **화면만 고치고 속은 안 고쳤다** | 규제 진실화(Q1)가 손님 눈에 보이는 화면·대출 계산·수집기는 한 파일로 묶었는데, **점수 계산만 옛 경로**(DB 컬럼 우선)로 남았다. 그래서 화면엔 "규제지역"이라 뜨는데 점수는 비규제로 매겨지는 단지가 생긴다. |
| **없앴다는데 다른 문으로 나온다** | Q6 이 "손님 화면에서 뺐다"고 한 6개 필드 중 **3개가 점수 탭으로 그대로 나온다**. 뺀 것은 서랍 한 경로뿐이었다. |

**결론**: "예전 거 그대로"는 과하지만, "새 상자에 옛 내용물"과 "앞문만 잠그고 뒷문은 열어둠"은 사실이다. 아래 §2 가 그 목록 전부다.

## 2. ⚠️ 리뉴얼했는데 옛것이 그대로인 자리 — 이 절이 핵심

### 2-1. 이름만 바뀌고 안은 그대로 — "격자 이사"

D4 의 대표 문장은 **"라벨:값 격자 폐지"** 다. 그런데 이번에 신설한 카드 3종의 속이 옛 격자와 **완전히 같다**. 직접 대조했다:

| | 옛 격자 (`DataSectionBlock.tsx:31-34`) | 신설 카드 (`BuildingInfoCard.tsx:66-69`, `TransportCard.tsx:34-37`) |
|---|---|---|
| 격자 | `display:"grid", gridTemplateColumns:"1fr 1fr", gap:"4px 12px"` | **같음** |
| 칸 | `display:"flex", justifyContent:"space-between", alignItems:"center", padding:"3px 0"` | **같음** |
| 이름표 | `fontSize:F.xs, color:C.muted` | **같음** |
| 값 | `fontSize:F.xs, fontWeight:600` | **같음** |

코드 주석이 스스로 인정한다 — `BuilderCard.tsx:30`·`BuildingInfoCard.tsx:57`: **"TransportCard 의 TC_S.container 와 byte-identical"**.

**즉 격자를 없앤 게 아니라, 접이식 상자에 넣고 뚜껑에 "건물 정보"·"시공사 정보"·"교통 상세"라는 새 이름표를 붙였다.** 재표현 5형태(막대·눈금 점·판정 칩·계단 칸·전국 위치+실값)를 적용받은 신설 카드는 **0개**다.

**게다가 격자가 늘었다.** 카드 3개가 새 격자 3개를 들여왔기 때문이다.

또 손님이 보는 화면에 옛 격자가 그대로 남아 있다. 직접 확인한 것만:

| 위치 | 파일:줄 | 남은 필드 |
|---|---|---|
| 종합 탭 "단지 기본정보" | `dataSections.ts:56-58` | units·unsold·heating (3) |
| 입지 탭 "치안/환경" | `dataSections.ts:84-85` | 6개 |
| 시세 탭 "이 동네 거래 시세" | `dataSections.ts:107-109` | housingPrice (1) |
| 분양 탭 "분양 안전" | `dataSections.ts:133-134` | cancelRatio6m (1) |
| 신설 카드 3종 | `BuildingInfoCard`·`TransportCard`·`BuilderCard` | 8 + 6 + 3 = 17 |
| 지역 통계 서랍 | `RegionStats.tsx:44-45` | 7 |

**커밋 제목이 실제보다 넓게 읽히는 문제도 있다.** PR #380 제목 "종합 탭 서랍을 0으로"는 **접이식 서랍(아코디언)**을 0으로 만들었다는 뜻인데, 제목만 보면 종합 탭에서 라벨:값이 사라진 것처럼 읽힌다. 실제로는 "단지 기본정보" 격자가 지금도 화면에 있다.

**⚠️ 사장님 결정이 필요하다.** D4 의 "격자 폐지"가 신설 카드 안쪽까지 포함하는가?
- **포함이면** → 카드 3종 + 지역 통계 서랍의 **24행을 판정 칩·막대로 재표현하는 작업이 통째로 남아 있다**. 어느 PR 에도 배정돼 있지 않다.
- **아니면** → 결정 원장의 D4 문구를 "격자를 주제별 카드로 묶는다"로 **정정**해야 한다. 지금은 문서와 코드가 어긋난 상태다.

### 2-2. 화면은 고쳤는데 점수는 옛것 — 규제 진실화의 뒷문

**가장 위험한 항목.** PR-1 은 "화면·LTV·수집기가 한 파일을 읽는다"가 목표였다. 실제로 화면(`getZone`)·대출 계산(`calcLTV`)·수집기(`regulation-seed.mjs`)는 전부 `src/data/regulation-zones.json` 하나를 읽는다. 여기까지는 완벽하다.

**그런데 점수 계산만 다른 문으로 들어간다.** 직접 읽은 코드(`src/scoring/scoreRisk.ts:125-131`):

```ts
// 규제지역: DB isRegulated 우선, null이면 getZone() 폴백
const zone =
  apt.isRegulated != null
    ? apt.isRegulated ? "regulated" : "normal"
    : getZone(apt.region as string, apt.gu as string);
```

**DB 값이 먼저고, JSON 파생값은 DB 가 비었을 때만 쓴다.** 문제는 그 DB 컬럼의 기본값이 `false`(비규제)라는 점이다 — 그러면 값이 **비어 있지 않으므로** `getZone()` 이 아예 발동하지 않는다. 새로 들어온 규제지역 단지가 "모름"이 아니라 "확인된 비규제"인 척하는 것이다.

시드(regulation-seed)는 **주 1회(일요일)**만 돈다. 그 사이 들어온 신규 단지는 다음 일요일까지 비규제로 채점된다.

- **운영 스냅샷 실측(2026-08-10, n=1,646)**: 화면 기준 규제 예상 301건 vs DB `true` 296건 → **5건 어긋남**. 전부 `false`인데 규제지역이어야 함 (서초·강동·동작·수원 영통·안양 동안). 5건 모두 `updated_at` 이 같은 시각 = 같은 배치로 들어온 신규 행.
- 비율은 0.30%로 작지만 **매주 재발하는 구조**다.
- **손님 눈엔 정상으로 보인다** — 화면은 `getZone` 을 쓰니까. **점수만 조용히 틀린다.** 눈으로는 절대 안 잡히는 종류다.

> 근거 등급: 코드 경로는 **내가 직접 확인**(scoreRisk.ts:125-131 직독). 운영 5건 불일치와 `DEFAULT false` 스키마는 **조사반 스냅샷 기반 — 재현 필요**(§7).

### 2-3. 없앴다는데 다른 문으로 나온다 — Q6 점수 탭 누출

Q6 은 "변별력 0 필드 6개를 손님 화면에서 뺀다"였다. 뺀 경로는 **`INTERNAL_ONLY_FIELDS`(`tabExtraFields.ts:239-249`)** 이고, 그 상수를 실제로 쓰는 곳은 **딱 한 줄**(`:277`, 여분 서랍 제외)이다.

**서랍 하나만 막았지, 점수 탭은 안 막았다.** `CatPanel.tsx:191-206` 이 펼쳤을 때 **모든 세부 항목의 이름과 값을 그대로 그린다**(직접 확인). 그래서 6개 중 3개가 손님에게 도달한다:

| 필드 | 점수 탭에 뜨는 모습 | 위치 |
|---|---|---|
| `quakeDesign` | 항목 "내진" — "적용"/"미적용"/"미수집…" | `scoreProduct.ts:148,156` |
| `energyGrade` | 항목 "에너지" — 수집률 0%라 **항상 "정보 없음"** = Q6 이 없애려던 "늘 미수집인 빈 줄"이 그대로 존재 | `scoreProduct.ts:125` |
| `sunlight` | 항목 "자연환경" 값에 `일조:양호` 가 끼어 들어감 | `scoreLocation.ts:174,179` |

나머지 3개(`hasPool`·`supplyRatio`·`hugGuarantee`)는 점수 계산에만 쓰이고 별도 항목이 없어 손님 도달 0.

**근본 원인**: `tabExtraFields.ts:242-243` 주석이 *"점수는 그대로 이 값들을 쓴다 … 화면에서만 내렸다"* 라고 적었는데, **점수 탭 표시를 "화면"으로 세지 않았다.** 지금 가드 테스트도 서랍만 검사한다.

**막기가 간단하지 않다** — `INTERNAL_ONLY_FIELDS` 로는 불가능하다. 점수 탭은 필드명이 아니라 항목명("내진"·"에너지"·"자연환경") 단위라 1:1 대응이 안 된다. 별도 장치가 필요하다.

### 2-4. 근거 문구가 옛 사실 — supplyRatio

`tabExtraFields.ts:248` 에 이렇게 적혀 있다(직접 확인):

```ts
"supplyRatio", // 실측 수집 0%
```

**운영 스냅샷(2026-08-10, n=1,646) 실측은 100.0% 채움**이고, 폴백으로 채운 행은 0, 시도별 고유값 16종(0.09~3.0)이다. **"수집 0%"도 "변별력 0"도 성립하지 않는다.**

더 걸리는 건 **일관성**이다. `supplyRatio` 는 `regions` 테이블에서 오는 **시·도 단위 값**인데, PR-2 가 같은 성격의 7종을 "이 지역 통계" 서랍으로 옮겼다. 특히 `housingSupplyLevel`(주택보급률)은 서랍에 **노출**하고 `supplyRatio`(인허가율)만 **완전 비노출**로 갈렸다 — 둘 다 같은 시도값인데.

한편 점수는 지금도 이 값을 쓴다(`scoreRisk.ts` 인허가율 보정 + 관리자 표 문자열).

> 세션 509(PR #381)가 "코드 옆 거짓 수치 3건"을 정정했지만 **이 줄은 대상에 없었다.**

### 2-5. 이름표만 새것 — `/apt/{id}` 는 D1 의 성과가 아니다

D1(팝업 → 독립 페이지)을 보고 "주소가 `/apt/…` 로 바뀌니 됐네"라고 읽기 쉬운데, **아니다.**

- `/apt/{id}` 주소 동기화와 검색 노출(사이트맵·프리렌더)은 **세션 503(PR #351)·세션 504** 가 만든 것이고, 이 재설계 계획(2026-08-09)보다 **앞선다**. `useUrlSync.ts:27-29` 주석에 세션 503 이 명시돼 있다.
- 지금 `/apt/{id}` 는 **"팝업을 여는 딥링크"**다. 화면은 여전히 `position:"fixed"` 오버레이(`DetailModal.tsx:353`).
- **"← 목록으로" 버튼은 존재하지 않는다** — 소스에 그 문자열 0건(주석 1건뿐). 닫기는 X 버튼.
- **D1 을 위해 새로 한 일은 0이다.**

**추가 함정**: "목록 스크롤·필터 복원"이 지금 되는 것처럼 보이는 이유는 **팝업 아래 목록이 계속 살아 있어서**일 뿐, 복원 장치가 하나도 없다(scrollY·sessionStorage 기반 복원 grep 0건). **페이지로 바꾸는 순간 손님이 스크롤과 "더 보기"로 늘린 30·60·90…을 전부 잃는다.**

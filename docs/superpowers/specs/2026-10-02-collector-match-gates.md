## 3. 구조

- **`scripts/collectors/_match-gates.mjs`(새 파일, 순수 함수만)** — 규칙은 여기 한 곳:
  - `completionMonthIndex(completion)` / `isMovedIn(completion, now)` — 완공월 판정. 문자열을 `new Date` 에 넣지 않는다(`probe-must-be-self-verified.md` §4-2). `src/scoring/scorePrice.ts parseCompletionMonth` 와 **같은 입력에 같은 답**이어야 한다(시험으로 맞댄다).
  - `cleanMatchName(name)` — 괄호 제거 + `stripRoundWords`(`_kakao-poi.mjs`) + 로마 숫자(Ⅰ·Ⅱ·Ⅲ…)를 아라비아 숫자로.
  - `namesCompatible(a, b)` — `phaseConsistent` · `blockConflict`(`_kakao-poi.mjs` — 이미 있는 판정을 다시 쓴다) + 로마 숫자.
  - `sameSigungu(apt, kaptItem)` — K2.
  - `pickKaptMatch(apt, kaptList, { now })` → `{ match, score } | null` + 탈락 이유(로그용) — K1·K5.
  - `usedateConsistent(completion, kaptUsedate)` — K4.
  - `pickNaverComplexForListing(apt, candidates)` — N1(거리·이름·차수 → 가장 가까운 것).
  - `inSiblingKaptWindow(now)` — R3.
- `_molit-api.mjs`: K-apt 전용 간격(`KAPT_MIN_INTERVAL_MS = 1500` — 모듈 안 마지막 호출 시각으로 기다림) · 결과 코드 검사(`KaptResultError`) · 목록 한 번에 · `SIDO_CODE` 강원 51 · 전북 52. `REQUEST_DELAY`(건축HUB 가 같이 쓰는 값)는 그대로 둔다. `findBestMatch` 는 지우지 않고 세 수집기가 `pickKaptMatch` 로 갈아탄다(다른 소비처가 있으면 그대로).
- 세 K-apt 수집기: 짝 짓기 교체 + K4 + K6 + R2(재시도 뒤에도 같으면 회차 중단 — `collector_runs` 에 실패, `error_message` 머리말 `KAPT_RESULT_<코드>` / 결과 코드 아닌 연속 실패는 `KAPT_FETCH_FAIL`) + R3(창 검사 셋 다 · 멈추면 `SIBLING_KAPT_WINDOW`) + 짝 동점이면 안 붙임.
- `sync-naver-complex.mjs`: Phase 4 = N1 + V6, Phase 1 = N2.
- `kosis-local-runner.mjs`: 관리비 줄 `--limit=300 --budget-min=40`(05:30 시작이면 06:10 전 종료 — 늦게 시작하면 창 검사가 멈춘다).

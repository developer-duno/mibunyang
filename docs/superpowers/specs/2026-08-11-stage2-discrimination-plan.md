# ②단계 — 데이터를 분별력 있게 (설계안)

> 사장님이 정한 순서: **①수집기 → ②분별력 → ③재배치 → ④시각화**
> 이 문서는 ②의 설계안이다. 실행 전 승인을 받는다.

## 이 단계가 풀어야 할 것 — 제품의 존재 이유

> "사용자 각각의 입장에 무엇을 중요하게 생각하고 각 입장에 필요한 점수를 매겨주는 게 우리가 해야 할 일"
> "점수를 막 주지 말고 분별력 있게 해야지, 우리는 상대평가잖아"

지금 이 둘이 **둘 다 안 되고 있다.** 아래는 전부 라이브 실측이다.

---

## 문제 1 — 프로필 맞춤이 사실상 작동하지 않는다 (최우선)

| 측정 | 값 |
|---|---|
| 실거주 ↔ 자녀교육 순위 상관 | **0.987** |
| 두 프로필 TOP10 겹침 | **8 / 10** |
| 실질 갈래 수 | **2개** ("투자" vs "나머지 넷") |

**원인은 구조다.** 프로필은 **6개 카테고리의 가중치만** 바꾼다. 그런데 자녀교육 손님이 실제로 중요하게 여기는
**학군**은 `location` 카테고리 **안에 묻힌 서브지표**라, `location` 가중치를 올리면 학군과 함께 교통·혐오시설·치안이
**통째로 같이 올라간다.** 실거주 프로필도 `location` 을 높게 주므로 두 프로필의 순위가 거의 같아진다.

### 처방안 — 서브지표 가중치 (프로필별)

카테고리 가중치는 그대로 두고, **카테고리 안에서 서브지표 비중을 프로필마다 다르게** 준다.

```
지금:  프로필 → 카테고리 가중치 → (서브지표 비중은 전 프로필 동일)
바꿈:  프로필 → 카테고리 가중치 → 프로필별 서브지표 비중
```

예 — `location` 안에서:

| 서브지표 | 실거주 | 자녀교육 | 신혼부부 | 은퇴 | 투자 |
|---|---|---|---|---|---|
| 학군 | 보통 | **최고** | 높음 | 낮음 | 보통 |
| 교통 | 높음 | 보통 | **최고** | 낮음 | 높음 |
| 의료 접근 | 보통 | 보통 | 낮음 | **최고** | 낮음 |
| 혐오시설 | 높음 | 높음 | 보통 | 높음 | 낮음 |

**⚠️ 실행 전 반드시 확인할 것**: 서브지표 비중을 바꿔도 **그 서브지표 자체에 변별력이 없으면 순위가 안 갈린다.**
학군이 A등급 84.4% 로 몰려 있으면 학군 비중을 최고로 올려도 손님끼리 구분이 안 된다.
**그래서 문제 2를 먼저 풀어야 한다.**

## 문제 2 — 몰림 지표: 비중을 올려도 안 갈린다

| 상태 | 개수 | 예 |
|---|---|---|
| 80% 이상이 한 값에 몰림 | **7개** | 학군 A등급 84.4% · 향 남쪽 93% |
| 전 단지 동일 = 변별력 0 | **6개** | (순위를 못 바꾸면서 점수만 부풀린다) |
| 카테고리 전체가 0점 | benefit | 전 단지 |
| 폭이 40~80 으로 좁음 | risk | |
| 73.5% 가 만점 동점 | env | ⚠️ **단순 클램프 금지** |

### 처방 원칙 (세션 501·498 에서 확립)

1. **경계는 실제값 분포에서 뽑는다.** 실측 없이 숫자를 정하면 만점 몰림이 반복된다(세 번째 사례가 되지 않게).
2. **만점 비율을 기준으로 고른다.** 상위 10%대가 만점이 되게(세션 498 실증: 만점 30.2% 는 "세 곳 중 하나가 동점"이라 비교 엔진이 비교를 못 한다).
3. **단순 클램프는 금지.** env 를 그냥 100 으로 자르면 **73.5% 가 전부 100 동점**이 된다 — 지금보다 나빠진다.
4. **변별력 0 지표는 점수에서 빼고 사실 라벨로 남긴다.** 모두에게 같은 점수를 더하는 건 순위를 안 바꾸면서
   점수만 부풀리는 일이다(혜택 카테고리를 이미 이렇게 처리했다 — PR #384).

## 문제 3 — 미래가치: 채우면 오히려 내려간다 (①과 맞물림)

**같은 법정동 63쌍 중 43쌍(68.3%)에서 "호재 있는 쪽"이 더 낮았다.** 평균 15.7점, 최대 36점.

원인 = `scoreFuture.ts:126-130` + `FUTURE_WEIGHT_MAP`. 호재가 **없으면** 그 몫이 인구(대개 고점수)로
100% 넘어가고, **있으면** 낮은 교통점수(24점)에 가중치가 곱해진다. **NULL 이 보상받는 구조다.**

그 결과 **884곳(53.7%)의 미래가치가 인구 하나로 결정**되고, 그 인구 값은 **고유값이 12개뿐**이다.
= 절반이 넘는 단지의 미래가치가 사실상 **12칸짜리 시도별 등급표**다.

### 처방안

1. **"모름"과 "확인된 없음"을 가른다.** 지금은 둘 다 0점이다. 이 저장소가 세션508 에 이미 정한 원칙
   (`src/scoring/CLAUDE.md` §"unknown(null) 처리") — *이진 필드는 `=== false`(확인된 부재)일 때만 불이익,
   null(모름)은 중립* — 이 **이 세 필드에만 적용 안 된 채 남아 있다.**
2. **동적 가중치 재설계.** 모름일 때 그 몫을 다른 축으로 100% 넘기지 않는다(넘기니까 역전이 났다).
3. **경계 재설계.** 지금 교통은 **만점 도달 불가**(시드에 '개통' 상태가 0개라 실제 최대 72점),
   도시개발은 **0/80 이진**이다. ①에서 자료를 넓히기 전에 이 경계부터 고친다 — **경계 먼저, 데이터 나중.**
4. **화면 문구 정정.** `fieldMeta.ts:471,479,480` 이 이 **세 필드만** NULL 을 `"없음"` 으로 번역한다
   (다른 필드는 `"미수집"`, 센티널은 `"반경 밖"`). **427곳은 값이 있는데도 "없음"** 이라 표시된다(판정 임계 40).
   ⚠️ **미래가치 3축에 한정해서** 고친다 — location 혐오시설 '없음' 478건은 점수 100(없어서 좋다)이라
   `"없음"` 을 일괄로 숨기면 좋은 소식까지 사라진다(`CatPanel.tsx:60-70` 주석이 경고하는 바로 그 지점).

## 실행 순서 (의존관계)

```
2-1  몰림·변별력 전수 재측정        → 어느 지표를 손볼지 확정 (읽기 전용, 위험 0)
2-2  경계 재설계 (만점 비율 기준)    → 2-1 결과 위에서만
2-3  미래가치 null 처리 + 동적 가중치 → ①의 자료 반영 전에 반드시
2-4  프로필별 서브지표 비중          → 2-2 가 끝나야 효과가 난다
2-5  검증: 프로필 간 상관·TOP10 겹침 재측정 → 0.987 이 얼마나 내려갔나
```

**2-3 이 ①의 관문이다.** 이걸 안 고치고 ①의 개발계획 자료를 기존 컬럼에 넣으면 **159곳이 내려간다.**
그래서 ①의 수집기는 **새 테이블에 적재**하고 점수 배선은 2-3 이후로 미룬다.

## 각 단계의 검증 방법

| 단계 | 무엇으로 확인하나 |
|---|---|
| 2-1 | 라이브 스냅샷 분포(만점 비율·고유값 수·상위 몰림률) |
| 2-2 | 경계 변경 전후 만점 비율 — 목표는 **상위 10%대** |
| 2-3 | 같은 법정동 쌍 역전율 — 지금 68.3% 가 얼마로 내려갔나 |
| 2-4 | 프로필 쌍별 순위 상관 — 지금 0.987 |
| 2-5 | TOP10 겹침 — 지금 8/10 |

**전부 뮤테이션으로 가드를 검증한다** — 새 경계·새 가중치를 되돌렸을 때 테스트가 red 가 되는지 확인한다.
통과만 보면 아무것도 안 지키는 껍데기가 남는다(이 저장소가 여러 번 당했다).

## 열어 둔 질문 (사장님 결정 필요)

1. **프로필별 서브지표 비중을 누가 정하나** — 내가 도메인 근거로 초안을 만들고 사장님이 조정하는 방식을 제안한다.
2. **점수가 내려가는 단지를 어떻게 알리나** — 2-3 을 하면 지금 부풀려진 884곳의 미래가치가 내려간다.
   정직해지는 방향이지만, 손님이 어제 본 점수와 달라진다.
3. **만점 비율 목표치** — 세션 498 은 13.9% 를 채택했다. 같은 기준을 쓸지.

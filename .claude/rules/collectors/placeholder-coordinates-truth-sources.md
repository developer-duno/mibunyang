# 자리표시 좌표 — 지오코딩 폴백이 만든 가짜 주소와, 정답을 구하는 세 출처의 우선순위

## 한 줄

**"주소가 있다"는 "위치를 안다"가 아니다.** `geocode-missing` 의 키워드 폴백이 구청 같은 대표 장소를 돌려주면
`reverse-geocode` 가 그 좌표를 **지번·도로명·법정동코드·동까지 갖춘 그럴듯한 주소로 세탁**한다. 그 결과
서로 다른 프로젝트 여러 개가 같은 지번·같은 좌표·같은 `naver_nearby_median` 을 공유한다.
정답은 **카카오 POI(이름) > 청약홈 공급주소(주소검색) > 단지명 매칭** 순으로 구하고, 어느 출처든
**시/군 단위 지역 게이트** 없이는 믿지 않는다.

## 사고 박제 (세션539~540, 2026-09-02~05)

소사역 프라힐스 15곳(651m)이 시작이었고, 같은 종류가 base 2,938곳 중 **209곳** 더 있었다(정정 완료).
가장 큰 무리 = `경기 용인시 처인구 김량장동 286`(처인구청·금령로 50) 19곳 — 힐스테이트 몬테로이·드마크
데시앙·에버랜드역 칸타빌 등 **서로 다른 개발사업 5종**이 구청 한 점에 겹쳐 있었다. 진짜 위치(포곡읍 전대리)와
**5.8km**, 최대 **21km**.

### 원인 = `scripts/collectors/geocode-missing.mjs` 폴백 사슬 (L155~185)

| 차수 | 무엇을 하나 | 왜 위험한가 |
|---|---|---|
| 1차 | 주소검색 `region gu dong` | 지번 없는 질의라 카카오는 **항상 `REGION`(동/구 중심점)** 을 준다 = 4차와 같은 자리표시. seed 가 `gu=고양시·dong=덕양구` 로 저장한 행은 다음날 **구 중심점**이 된다 — 세션541 도메인 리뷰가 잡은 뒷문(삭제) |
| **2차** | 키워드 `region gu 단지명` **top-1 무검증** | 단지명이 안 잡히면 지역명이 지배 → **구청·주민센터**가 1위 |
| **3차** | 키워드 `단지명` **지역 게이트 없음** | "힐스테이트"·"더샵" 등 전국 공용 브랜드 → **수백 km 밖 단지** |
| 4차 | 주소검색 `region gu` | **시군구 중심점**을 좌표로 저장 — 설계상 자리표시 |
| 5차 | 블록 번호 뗀 이름 키워드 | 2·3차와 같은 위험 |

어느 차수든 **정밀도를 기록하지 않고** `lat/lng` 만 쓴다. 그 뒤 `reverse-geocode.mjs` 가 `address IS NULL`
행을 역지오코딩해 `address·road_address·bjd_code·lot_main/lot_sub·dong` 을 채우므로, 구청 좌표가
"김량장동 286 / 금령로 50 / 4146110100 / 286-0 / 중앙동" 이라는 **완전한 가짜 주소**가 된다.
`collect-naver-listings.yml`(매일)·`backfill-new-apartments.yml` 이 둘을 연달아 돌리므로, 주간 청약홈
seed 가 블록식 주소("덕은도시개발구역 A4블록")를 넣으면 **하루 안에** 같은 방식으로 오염된다.

## 정답 출처와 신뢰도 (양성 대조군으로 검증)

**모든 탐침은 먼저 답을 아는 단지로 시험했다**([[probe-must-be-self-verified]]) — 소사10차(네이버 실단지와 13m)·
이미 고쳐 카카오로 확정한 단지들.

| 순위 | 출처 | 검증 | 조건 |
|---|---|---|---|
| **1** | **카카오 키워드 POI** `search/keyword.json` | 소사10차 16m · 107곳 중 78 확정 · 청약홈과 다툰 대조 3/3 승 | `category_name` 에 `아파트\|주택`, `모델하우스\|견본\|중개\|분양사무\|홍보관` 제외, `address_name` 이 단지 시도로 시작, `stringSimilarity(질의, place_name)≥0.7`. **강함** = ≥0.85 **또는 공백 제거 질의가 place_name 의 부분문자열**("등촌역한울에이치밸리움" ⊂ "…1차아파트" — 접미어가 점수만 깎는 진짜 일치) |
| **2** | **청약홈 `HSSPLY_ADRES` 지오코딩** `search/address.json` | ah-* 1,556/1,556 로스터 커버 · 단지명 매칭의 서브브랜드 오류 2건 적발 | `address_type ∈ {REGION_ADDR, ROAD_ADDR}` 만(REGION = 동 중심점 **거부**, 키워드 폴백 **금지**). 정규화 = 괄호 제거 → 쉼표/`외 N필지` 앞 첫 필지 → `번지`·`일원` 제거. 건전성 = 질의의 읍/면/동/리 토큰(끝 숫자 제거: 학익2동→학익동)이 결과에 포함. 카카오 POI 가 있으면 POI 가 이긴다(대조군 3건: 청약홈 주소가 사업부지 표기라 2~4km 벗어남) |
| 3 | `complexes` 이름 매칭 | 107 중 ~10 오류 | 시/군 키(광역시는 **시도+구** — "남구·중구"는 여러 광역시에 있다), sim≥0.75, **차수 일관성**(2단지↔1BL 거부, 센트럴↔퍼스트·타워↔파크 같은 서브브랜드는 sim 0.8 로도 통과하니) **1·2 뒷받침 없으면 sim≥0.9 + 차수 일치만** |

### 판정 (현재 좌표와 300m 기준)

어느 출처든 ≤300m → **이미 정상**(손대지 않음) · K∧A 서로 ≤300m 이고 현재와 >300m → **A2** ·
A 단독 / K 강함 단독 → **정정** · K 약함 단독 → **보류** · K↔A 서로 >300m → **충돌(사람 판단)** ·
출처 없음 → 그대로(단, **다른 핵심이름 2종 이상이 소수5자리 동일 좌표**를 공유하면 "진짜 자리표시" 로 표기).

## 정정할 때 함께 해야 하는 것

1. **부속 필드 재정합** — `address/lat/lng` 만 고치면 `dong/bjd_code/lot_main/lot_sub/road_address` 가 옛 자리표시
   값으로 남는다(209행 전부 그랬다). `bjd_code` 는 건축HUB 조회 키라 **남의 건물 정보가 붙는다**. 새 좌표로
   `coord2regioncode`+`coord2address` 를 다시 돌려 채운다(`address` 는 정답 출처 표기 유지).
2. **파생표 정리는 시간창에서만** — [[purge-to-recollect-timing]]. `transport`·`schools` 는 행 삭제, `infra` 는
   kakao 소유 9컬럼만 null(행 통째 삭제 금지 — childcare/police/emergency 가 같은 행을 쓴다).
3. **자기 감사** — 정정 직후 정정하지 않은 출처로 다시 잰다. 세션540은 107건을 카카오로 재감사해 **내 오류 5건**
   (차수 착오 1·서브브랜드 착오 4)을 잡았고, 제3 신호(`coord2regioncode` 시도/시군구 대조)로 209건을 재검했다.

## 재발 방지 (근본 처방 — 세션541 적용)

오염 통로는 **셋**이었다(세션540 메모리는 ①②만 알았다 — 세션541 조사에서 ③ 발견):

| 통로 | 자리 | 옛 동작 | 실측 |
|---|---|---|---|
| ① | `geocode-missing.mjs` 2·3·5차 키워드 폴백 | `size=1` 1위 무검증 | 이름이 안 잡히면 지역명이 지배 → 구청 |
| ② | 같은 파일 4차 `region gu` 주소검색 | 시군구 중심점(`address_type: REGION`)을 좌표로 저장 | `경기도 용인시 처인구` → 중심점 |
| ③ | `collect-applyhome-seed.mjs` `geocodeAddr` 키워드 폴백 | 청약홈 **주소 문자열**을 키워드로 던져 1위 채택 | `덕은도시개발구역 A4블록` → **DMC자이더리버**(다른 단지) |

③은 **주간 seed 가 새 단지를 넣는 그 순간**에 오염시키므로 ①②만 막으면 재발한다. 블록식 주소는 카카오
**주소검색**에서 전부 0건이라 seed 의 주소검색 1차 자체는 안전하다(실측).

처방 = 세 통로가 **한 규칙**을 쓰게 했다: `scripts/collectors/_kakao-poi.mjs`
(정정 도구의 `pickKakaoCandidate` 를 옮긴 공유 모듈 — 도구는 re-export).

- `geocodeApartmentByName({ name, sido, gu })` 가 `sido gu 이름` → `이름` → `블록 뗀 이름` 순으로 묻고, 각 결과
  15건에서 **카테고리 아파트/주택 · 모델하우스류 제외 · 지역 게이트(첫 토큰이 시도, 다음 토큰이 시군구와 정확히
  일치) · 이름 유사도 ≥0.7** 을 지난 것만 채택. 약함(0.7~0.85)은 **시군구 게이트를 실제로 거쳤을 때만**(세종은
  시도=시 라 허용) — 시도만 걸면 "양주역중흥S-클래스 → 수원 중흥S-클래스"(sim 0.8) 55km 오탐이 통과한다.
- 4차(시군구 중심점)는 **삭제**. 못 찾으면 null 로 둔다 — 정직한 null 이 가짜 정밀보다 낫고, `reverse-geocode` 는
  `lat IS NOT NULL` 만 보므로 세탁도 일어나지 않는다. 정적 JSON 은 좌표 없는 단지를 빼지 않는다(화면에서 안 사라짐).
- **1차 주소검색(`region gu dong`)도 삭제** — 독립 리뷰가 잡은 뒷문. 지번 없는 질의는 카카오가 항상 `REGION`
  중심점을 주고, 그건 4차와 같은 자리표시다(실측: seed 의 `parseAddress` 가 블록식 주소를 `gu=고양시·dong=덕양구`
  로 저장 → 다음날 1차가 **구 중심점**). 이제 `geocode-missing` 은 **단지명 POI 하나만** 쓴다.
- **seed 의 주소검색은 `isPreciseGeocode`(REGION_ADDR/ROAD_ADDR + 읍면동 건전성) 통과분만** 좌표로 쓴다 —
  정정 도구의 판정 함수를 `_kakao-poi.mjs` 로 옮겨 같은 잣대를 공유한다.
- **"못 찾음"은 실패가 아니라 skip** 이다. 옛 4차가 거의 늘 값을 주던 자리라 이제 null 이 정상 결과인데, 그걸
  `failed` 로 세면 lat null 행 하나로 매일 step 이 죽어 뒤 step(reverse-geocode·전용률)이 건너뛴다
  (`collect-naver-listings.yml` 에 `continue-on-error` 없음). `collector_runs.skip_count` 가 "미확정 N건" 이다.
- ⚠️ 부작용: seed 의 정밀 중복 판정(`findDuplicate`)은 좌표 없으면 **보류(다음 주 재시도)** 다. 옛날엔 구청 좌표로
  억지 판정됐던 자리라 보류가 더 정직하지만, 매주 보류가 쌓일 수 있다 — seed 로그 `보류 N건` 을 본다.
- 지역 게이트에 쓰는 카카오 `address_name` 실측 표기: `경남 창원시 …`·`강원특별자치도 원주시 …`·`세종특별자치시 한솔동 …`·
  `전북특별자치도 전주시 덕진구 …` → 첫 토큰이 시도 약칭으로 시작, 다음 토큰(들)이 시군구. DB `gu` 는 한 단어
  (`양주시`) 또는 두 단어(`용인시 처인구`), 세종은 null. 시군구 비교는 **토큰 정확 일치**(`동구` ⊂ `남동구` 오탐 차단).
- 정정 도구 = `scripts/fix-placeholder-addresses.mjs`(v2, 3출처 교차·dry-run 기본·`--ids-file` purge).

## 안티 패턴

- ❌ "주소·지번·법정동코드가 다 있으니 위치가 맞다" — 전부 한 좌표에서 역산된 값일 수 있다
- ❌ 이름 유사도만으로 좌표 옮기기 — 브랜드명 충돌·차수 착오·서브브랜드 착오 세 종류가 실측됐다
- ❌ "두 출처가 어긋나면 더 그럴듯한 쪽" — 대조군으로 **어느 쪽이 지는지** 먼저 재라(청약홈 주소는 사업부지 표기일 수 있다)
- ❌ 좌표만 고치고 부속 필드 방치
- ❌ `naver_presale_no` 로 좌표 되찾기 — 링크가 오염돼 있다

## 도구 v2 의 알려진 구멍 (세션541 실측 — 후보는 반드시 눈으로 본 뒤 `--apply`)

- **읍면동 토큰이 없는 청약홈 주소는 건전성 검사가 건너뛰어진다.** `경기도 파주시 파주운정1`(디에트르 센트럴 A36BL) 을
  카카오 주소검색이 `REGION_ADDR 경기 파주시 신촌동 1` 로 돌려줬고 `isPreciseGeocode` 가 통과시켜 **B_apply 로 5.3km
  엉뚱한 곳**을 제안했다. 진짜 위치는 POI `산내마을5단지파주운정신도시디에트르센트럴아파트(A36BL)` 목동동 916.
- **부분문자열 승격이 유사도 하한(0.7) 검사 뒤에 있다.** 청약홈 이름은 단지명 앞뒤에 마을·블록 접두어가 붙어
  (`산내마을5단지…`, `송도국제도시 F20-1블록 …`) LCS 유사도가 0.67 로 떨어지면 **진짜 일치 POI 를 하한에서 버린다.**
  그래서 송도프라임뷰(POI 8m 일치)도 K 없이 A 단독으로 잡혔다. 승격 규칙을 하한 앞으로 옮기되 짧은 질의(브랜드명만)
  오탐을 막을 최소 길이 조건이 필요하다 — 미적용(후속).

# 행정구역 개편 — 코드표를 바꾸기 전에 **소비처 API 마다 raw 1회**, 바꾼 뒤엔 **저장 데이터도 옮긴다**

## 한 줄

**행정구역이 개편되면 법정동코드 접두가 바뀌고, 우리가 박아 둔 정적 코드표는 그날부터 조용히 거짓이 된다.**
외부 API 는 옛 코드에 **에러 대신 0건**을 돌려주므로 `collector_runs` 는 success, 수집기 로그는 "0건 수집",
모니터는 침묵한다. 이 저장소는 이 사고를 **세 번** 겪었다 — 강원 42→51 · 전북 45→52 · 전남광주 46/29→**12**.

## 사고 이력

| 개편 | 시행 | 우리가 겪은 일 |
|---|---|---|
| 강원특별자치도 | 2023-06-11 | `SIDO_CODES` 에 `4200000000` 이 남아 인구 응답이 **빈 값** — 세션285 raw 검증에서 발견 |
| 전북특별자치도 | 2024-01-18 | 같은 꼴(`4500000000`) — 같은 세션에 함께 정정. 2개월(61일) 누락 |
| **전남광주통합특별시** | **2026-07-01** | 광주 `29`·전남 `46` **동시 폐지 → 둘 다 `12`**. 5개 층이 6~7월부터 끊긴 것을 **2026-09-10** 에야 발견(3개월 잠복) |

세 번째가 앞의 둘보다 나쁜 이유: **두 시도가 한 접두를 공유**하게 되어 `접두 → 지역` 역변환이
**모호**해졌다. 표 하나를 뒤집어 쓰던 자리(`C1_TO_REGION`)가 전부 재설계 대상이 된다.

## 1. 표를 바꾸기 **전** — 소비처 API 마다 raw 1회 (옛/새 대조)

**전환 시점은 API 마다 다르다.** 이게 이 룰의 핵심이다. 2026-09-10 같은 날 실측:

| 소비처 | 옛 코드 | 새 코드 | 판정 |
|---|---|---|---|

| 건축HUB `BldEngyHubService` sigunguCd | 202604~ **0건** | 같은 건물 202604·05 정상 | 새 코드만 |

| 행안부 인구 `stdgPpltnHhStus` stdgCd | 202607~ `NODATA_ERROR` | `1200000000` = 27 시군구 | 새 코드만 |

```bash

# (probe-must-be-self-verified §1: 답이 나와야 하는 입력으로 먼저 도구를 시험한다)
```

## 3. 두 시도가 한 접두를 공유하면 — **단일값 표에 넣지 마라**

`REGION_MAP` 은 시도명 하나 → 약칭 하나인 표다. 여기에 `"전남광주통합특별시": "전남"` 을 넣는 순간
**광주 5구까지 전남으로 오라벨**된다(반대로 넣으면 전남 22 시군이 광주가 된다). 그래서:

- 통합 이름은 **`REGION_MAP` 에 넣지 않는다.**
- 판정은 `resolveRegionName(sidoFull, gu)` 하나가 독점한다 — **시군구 이름으로만** 가른다.
- gu 가 비면 **null 을 준다.** 시도 단위 합계행은 못 가르는 게 사실이고, 조용히 한쪽에 붙이면
  그 지역 인구·순이동이 통째로 틀어진다. 호출자가 skip 할지 결정한다.

### 부분 매칭이 있는 자리는 **이름을 열거하지 말고 "모호하면 포기"**

```js
// 빨강 1 — "전남광주통합특별시".includes("광주") 가 참 → 27 시군구 전부가 광주로 붙는다
for (const [k, v] of Object.entries(REGION_MAP)) if (fullName.includes(v)) return v;

// 빨강 2 — 그 이름 하나만 막기. 표기가 한 글자만 달라지면 그대로 빠져나간다
//          ("전남광주특별시" 는 이 정규식에 안 걸리고 → 광주로 굳는다. 세션545 적대검증 실증)
if (/통합특별시/.test(fullName)) return null;

// 초록 — 둘 이상 걸리면 판정하지 않는다. 이름을 몰라도 막힌다
const hits = new Set();
for (const [k, v] of Object.entries(REGION_MAP)) {
  if (fullName.includes(v) || k.includes(fullName)) hits.add(v);
}
return hits.size === 1 ? [...hits][0] : null;
```

**폴백이 원문을 그대로 돌려주는 함수는 그 값을 저장하기 전에 반드시 검증한다.**
`reverse-geocode.normalizeRegion` 은 못 가르면 `?? name` 으로 카카오 원문을 돌려주는데, 그걸
검증 없이 `apartments.region` 에 쓴 결과가 **"전남광주통합특별시" 6곳**이었다(세션545 정정 대상).
그 행은 17지역 필터 어디에도 안 잡히고 지역 지표 조인도 끊긴다 — `VALID_REGIONS` 통과분만 쓰고,
아니면 **건너뛰고 skip 으로 센다**(실패가 아니다). 같은 꼴이 `collect-data.mjs` 의
`else if (areaName) region = areaName;`(청약홈 원문 무검증 대입)에도 있었다.

**표에서 키를 꺼낼 땐 `hasOwnProperty`.** `map?.[gu]` 는 `gu` 가 `"constructor"`·`"toString"` 이면
**함수를 돌려준다** — 그 값이 LAWD_CD 로 URL 에 실린다(세션545 적대검증 실증, `getLawdCd` 에서 발견).

같은 함정이 **주소 문자열 전수 순회**에도 있었다. `naver-presale.mjs` 의 옛
`address.includes(full)` 는 `"경기도 광주시 양벌동"` 을 광주광역시로 붙였다(실측 5곳).
**시도는 첫 토큰이 결정한다** — 주소 전체를 훑지 않는다.

## 3-1. 개편은 **코드만 바꾸는 게 아니라 시군구를 새로 만들고 합친다** — 집계가 조용히 틀어진다

시도 접두만 보면 놓친다. 같은 개편 물결에서 **시군구 단위 자체가 바뀌고**, 우리 집계 코드는 그걸 모른다.
2026-09-10 인구 수집 실측(17시도 전수 대조, 15개는 오차 0)에서 **두 갈래**가 드러났다:

| 갈래 | 실측 | 왜 |
|---|---|---|
| **접힘 → 이중 계상** | 경기 시도행 **+999,673**(1,477만 vs 실제 1,360만) | 행안부는 `화성시`(999,673)와 `화성시 만세구/효행구/병점구/동탄구`를 **따로** 준다. 별칭표가 4구를 "화성시"로 접어 **저장은 1행**인데, 시도 집계는 **접기 전 5행을 다 더한다**. 부모 제외(`pickParentCities`)도 접힌 이름(공백 없음)을 보므로 안 걸린다 |
| **신설 구 → 통째 유실** | 인천 시도행 **−903,298**(216만 vs 실제 306만) | 2026 인천 개편으로 중구·동구 → 제물포구·영종구, 서구 → 서해구·검단구. 네 구 합이 **정확히 903,298**. `if (!curPop || !prevPop) continue` — **전년 동월에 없는 키라 행 자체를 버린다**. DB 엔 `population = null` 로 남는다 |

- **증감률은 전년 비교라 개편 첫 1년이 통째로 위험하다.** 신설·통합·분구가 있으면 그 시군구의 전년 값은 **존재하지 않는 게 정상**이다.
  없다고 버리면 인구가 사라지고, 옛 키로 억지 매칭하면 증감률이 거짓이 된다. **값은 저장하고 증감률만 `null`** 이 정답.
- **접기(별칭 정규화)와 집계(합산)는 같은 단계에서 해야 한다.** 접은 뒤에 세거나 접기 전에 제외 판정을 하면 한쪽이 반드시 어긋난다.
- 판별법: 시도별로 **행안부 원문 합계 vs 우리 시도행**을 맞대라. 15개가 0인데 두 곳만 크게 벌어지면 그 두 곳이 개편 지역이다.

```bash
# 시도 하나의 원문을 그대로 받아 접힘 충돌과 합계를 본다
node --input-type=module -e "import { loadEnv, normalizeGu } from './scripts/collectors/_shared.mjs'; loadEnv(); /* stdgCd 로 조회 후 sggNm 별 normalizeGu 결과를 세어 2개 이상 모이는 키를 찾는다 */"
```

## 4. 바꾼 뒤 — "0건" 을 사고로 세는 감시가 없다

이번 사고가 3개월 잠복한 이유는 **어느 신호도 울리지 않았기 때문**이다:
`collector_runs` 는 success, 수집기는 "0건 수집" 을 정상 종료로 처리, monitor ⑤(신선도)는
수집기가 매 회차 잘 도니까 침묵. [[tool-output-illusion-guard]] §"collector_runs 정상 = 데이터 정상" 의 실물이다.

- 개편 뒤 **첫 정기 회차 로그에서 그 지역 건수 > 0** 을 눈으로 확인하는 것까지가 작업이다.
- 지역별 "최근 N개월 0건인데 API 는 >0" 가드는 BACKLOG 후보(세션545).

## 5. 이미 빈 기간은 **백필해야 채워진다**

코드표를 고치면 "앞으로" 만 정상이다. 끊긴 동안의 공백은 남는다 —
거래는 `--months=N --only=<region>:<gu>` 로, 인구는 해당 회차 재실행으로 메운다.
백필 대상 지역·개월은 개편 시행일과 각 API 의 전환 시점으로 계산한다(§1 표).

## 6. 작업 트리는 로컬 러너의 **운영 코드**다 — 코드표 편집은 worktree 에서

`F:\mibunyang` 작업 트리를 Windows 스케줄러가 그대로 실행한다(월/목 08:00 네이버 파이프라인 · 매일 04:30
어린이집 · 05:30 KOSIS/MOLIT 러너). 세션545 목요일 작업 중 10:13 에 `naver-presale.mjs` 가 떴고, 코더가
같은 시각대에 `_shared.mjs`·`naver-presale.mjs` 를 편집하고 있었다. 로그의 "[목록] 광주 조회… / 전남 조회…"
(옛 코드의 분리 출력)로 **편집 전 파일을 읽었음**을 확인해 오염은 없었지만 몇 분 차이였다.
→ 코드표·수집기 여러 파일을 걸치는 편집은 **git worktree** 에서 하거나 스케줄러를 잠시 끈다.
검증 = 그 시각 `collector_runs` 행 + 파이프라인 로그의 출력 형태가 옛/새 어느 코드인지 대조.

## 안티 패턴

- ❌ "표를 새 코드로 바꿨으니 끝" — 저장된 `bjd_code`·이미 빈 기간이 남는다(§2-9, §5)
- ❌ "`REGION_MAP` 을 쓰는 곳을 다 고쳤다" — 이름표를 안 쓰고 **주소 첫 토큰을 직접 자르는** 파서가 따로 있다(§2-11, 세션545 리뷰어 적발)
- ❌ 분할 헬퍼를 "A 아니면 B" 로 — 시군구가 아닌 토큰(지구·블록)이 한쪽에 조용히 붙고, 그 전엔 켜지던 폴백(청약홈 지역코드)이 꺼진다. **양쪽 명단에 없으면 null**
- ❌ 작업 트리에서 여러 날 걸치는 편집 — 로컬 러너가 미커밋 코드를 운영에서 돌린다(§6)
- ❌ "모든 API 가 같은 날 바뀐다" — KOSIS 는 두 달 뒤에도 옛 코드를 줬다(§1)
- ❌ 통합 시도명을 `REGION_MAP` 에 추가 — 한쪽이 통째로 오라벨(§3)
- ❌ `includes` 부분 매칭에 통합 이름을 흘려보냄 — 27 시군구가 한 지역으로(§3)
- ❌ "0건이니 그 지역에 거래가 없었나 보다" — 옛 코드는 **에러 대신 0건**을 준다(§4)
- ❌ 접두 역변환 표를 그대로 뒤집어 씀 — 공유 접두가 생기면 **모호**하다(§2-8)

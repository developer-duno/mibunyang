# App.tsx 줄 수는 비대의 증거가 아니다 — 배선 루트 판별 의무 — 이력 (자동 로드 안 됨)

규칙 본문은 `.claude/rules/meta/composition-root-not-bloat.md`. 이 파일은 그 규칙이 생긴 사건·수치·답습 자산 기록이며 세션에 자동으로 실리지 않는다.

## 사고 박제 (세션 485)

AI 개발환경 감사에서 **"App.tsx 977줄 단일 파일"을 위험 병목 Top5 에 올리고**, 2차 계획에
"JSX 520줄을 sections 컴포넌트로 분할(트랙 E-2)"을 넣었다. 착수 직전 실측하니 **전제가 틀렸다.**

| 실측 (세션 485, App.tsx 925줄 시점) | 값 |
|---|---|
| JSX 구간 총 줄수 | 523 |
| **그 중 prop 전달 줄** | **229 (44%)** |
| `tab === "home"` 분기 | `<HomePage>` **props 25개 호출 하나** (26줄) |
| `tab === "list"` 분기 | 113줄 (인라인 마크업 ~50 + `<AptListSection>` props 38개) |
| `info`/`admin`/`upcoming` 분기 | 각 20~32줄, 전부 컴포넌트 호출 |
| useState / useCallback | **4개 / 7개** (로직은 이미 커스텀 훅 13개로 추출됨) |

**컴포넌트는 이미 전부 분리돼 있었다.** App.tsx 는 **배선 루트(composition root)** 이고,
배선 루트의 본업이 prop 을 넘기는 것이다. 여기서 `<HomePage>` 블록을 새 컴포넌트로 빼면
App.tsx 의 25줄 prop 목록이 새 파일로 옮겨가고 **25개짜리 타입 인터페이스가 하나 더 생긴다.**

### 실증 — 같은 세션의 E-1 이 증거

`useUrlSync` 추출(자족적 useEffect 3개, 진짜 응집 단위):
`App.tsx -52줄` / `useUrlSync.ts +107줄` = **전체 순증 +55줄**.
응집도 높은 로직 추출조차 총량은 늘었다. 응집도 없는 prop 목록 이동은 순증 폭이 더 크고,
그 대가로 prop 수십 개를 새 경계로 통과시키는 회귀 위험만 진다.

## 답습 자산

- 세션 485 트랙 E-1 (`src/hooks/useUrlSync.ts`) = 응집 단위 추출의 **정답** 사례(순증 감수할 가치 있음)
- 세션 485 트랙 E-2 = 실측 후 **폐기**한 사례(사장님 승인, 미실행)
- [[tool-output-illusion-guard]] — "가공된 신호(줄 수)를 1차 진실로 가정" 의 같은 결

# 측정 도구부터 의심하라 — 탐침에 양성 대조군을 붙인다 — 이력 (자동 로드 안 됨)

규칙 본문은 `.claude/rules/meta/probe-must-be-self-verified.md`. 이 파일은 그 규칙이 생긴 사건·수치·답습 자산 기록이며 세션에 자동으로 실리지 않는다.

## 사고 박제 (세션537, 2026-09-01)

| # | 무엇 | 어떻게 드러났나 | 위험 |
|---|---|---|---|
| 1 | 없는 컬럼(`prices.trade_type`) 조회 | `data` 가 `null` 로 와서 "재료가 없다"고 오판 | 근거 없이 반영할 뻔 |
| 2 | **동명 단지 4건 중 첫 건만** 봄 | 다른 id 에 재료가 있었다 | 같은 오판 |
| 3 | `Number(null) === 0` | **빈칸을 0으로 셌다**(`0 = 553` 이 빈칸 553 과 정확히 같은 게 증거) | 대상 산정 오류 |
| 4 | **함수 시그니처를 안 읽고 호출** | 실제 `findNearbyComplexes(apt, grid, radiusKm)` 인데 `(grid, lat, lng, meters)` 로 부름 | **"채울 수 있는 곳 0"** 이라는 무효 결과 → 멀쩡한 개선(356곳 후보)을 폐기할 뻔 |
| 5 | `Number(null)` 함정에 **또** — `complexes` 쪽만 안 고침 | 적대검증이 잡음. NULL 15,647건을 "0이 15,647건"으로 **코드 주석·커밋 메시지에 박제** | 거짓 근거로 코드 변경을 정당화 |

4번이 가장 위험했다 — **틀린 결과가 "아무것도 할 게 없다"** 였기 때문에, 그대로 믿었으면
조용히 덮였다. 실패가 요란하지 않은 오측정이 제일 무섭다.

## 차단 검증

| 사고 시나리오 | 본 룰 적용 시 |
|---|---|
| 잘못된 인자로 호출해 "대상 0곳" | §1 양성 대조군에서 즉시 드러남 |
| `Number(null)` 로 빈칸을 0으로 셈 | §2 `!= null` 선행 |
| 조회 실패를 "재료 없음"으로 오판 | §4 `.error` 출력 |
| 동명 단지 첫 건만 보고 단정 | §5 전부 세기 + 좌표 확인 |
| 한 곳만 고치고 같은 함정 재발 | §2 ⚠️ 다른 자리 확인 |

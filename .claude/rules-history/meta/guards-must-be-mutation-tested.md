# 안전장치는 "고장 내서" 검증한다 — 통과만 보면 껍데기가 남는다 — 이력 (자동 로드 안 됨)

규칙 본문은 `.claude/rules/meta/guards-must-be-mutation-tested.md`. 이 파일은 그 규칙이 생긴 사건·수치·답습 자산 기록이며 세션에 자동으로 실리지 않는다.

## 사고 박제 (세션 491, 2026-08-05)

같은 세션에서 **두 번** 났다. 둘 다 뮤테이션(일부러 고장 내기)이 아니었으면 못 잡았다.

### ① 새 감사 스크립트가 정상을 오판 — 통과를 못 해서 즉시 드러남

`scripts/audit-playwright-cache.mjs` 신설. `extractCacheKeys` 정규식을 `\S+`(공백 없는 문자)로 썼는데, 실제 캐시 키는 `pw-${{ runner.os }}-1.61.1` 로 **`${{ }}` 안에 공백이 있다.** 거기서 잘려 정상 상태를 "키 없음"으로 판정했다.

```js
// 빨강 — ${{ }} 안 공백에서 잘린다
const m = line.match(/^\s*key:\s*(pw-\S+)\s*$/);

// 초록 — 줄 끝까지 non-greedy 로 받고 뒤 공백만 떼어낸다
const m = line.match(/^\s*key:\s*(pw-.+?)\s*$/);
```

이건 **방향이 운 좋았다** — 정상이 통과를 못 해서 바로 드러났다. 반대 방향이었다면(고장을 안 잡는 쪽) 통과만 보고 넘어갔을 것이다.

### ② 테스트 12건 통과인데 가드는 아무도 안 지킴 — 뮤테이션이 아니면 영영 못 봄

`noxious.mjs` 의 `buildNoxiousRow` 에 `Number.isFinite` 가드를 넣고 테스트 12건을 붙였다. **전부 통과.** 그런데 그 가드를 **지워도 전부 통과**했다.

```js
// 가드
const hasFinding = found.length > 0 && Number.isFinite(minDist);

// 이렇게 지워도 테스트 12건이 전부 통과했다
const hasFinding = found.length > 0;
```

원인: 테스트가 `buildNoxiousRow("b", [], Infinity)` 만 봤다. 그 경우엔 `found.length > 0` 이 이미 false 라 **가드가 없어도 null 이 나온다.** 가드가 진짜 필요한 건 **"발견은 있는데 거리를 못 구한"** 경우다.

```js
// 이 케이스를 추가하고서야 뮤테이션이 잡혔다 (2건 red)
it("발견이 있어도 거리가 Infinity 면 null 로 막는다", () => {
  expect(buildNoxiousRow("d", ["장례식장"], Infinity).noxious_dist).toBeNull();
});
```

### ⚠️ 그 "주석을 걷어낸 사본" 자체가 코드를 먹을 수 있다 (세션531)

위 처방("주석을 걷어낸 사본에 돌린다")을 그대로 따랐는데도 가드가 죽어 있었다.
스트리퍼가 `/\*[\s\S]*?\*\//g` 로 **아무 데서나** 블록 주석을 찾았기 때문이다.
`naver-presale.mjs` 의 `HEADERS` 에는 이런 줄이 있다:

```js
"Accept": "application/json, text/plain, */*",
```

문자열 안 `*/*` 의 `/*` 가 **가짜 주석 시작**으로 읽히고, 그 뒤 첫 `*/`(다음 JSDoc 닫기)까지
**1,857자·34줄이 통째로 지워졌다.** 그 구간(CLI 인자 선언부 전체)을 겨누는 가드는
**무엇을 넣어도 통과한다** — 검사 대상이 애초에 없기 때문이다.

### ⚠️ 그 결함을 고치는 가드조차 **표적을 잘못 고르면 껍데기다** (세션539)

세션531의 처방을 그대로 따라 `_exit-quota-coverage.test.mjs` 의 스트리퍼를 고치고 회귀 테스트를
붙였는데 **뮤테이션이 green** 이었다(128건 전부 통과). 가드가 하나도 안 지키고 있었다.

원인은 **표적을 지워지는 구간 바깥에서 골랐다**는 것이다. 옛 정규식은 `*/*` 의 `/*` 부터
**다음 `*/`(대개 아래 JSDoc 의 닫기)까지**를 먹는다. 내가 겨눈 줄은 그 `*/` **뒤**라 옛 판본에서도
멀쩡히 살아남았다 — "결함이 있어도 통과"하는 검사를 쓴 것이다.

세션539 실측 — `naver-presale.mjs` **32줄**(57~95) · `naver-listings.mjs` 11줄(81~91) ·
`naver-devplan.mjs` 11줄(120~130) 이 사라졌고, 세 파일 공통으로 그 구간에 있는 `sec-fetch-site` 를
표적으로 바꾼 뒤에야 뮤테이션 **4건 red** 가 났다.

### ⚠️ 줄머리 고정만으로는 부족하다 — 두 위험이 **반대 방향**이다 (세션539)

세션531의 `^[ \t]*` 고정만 걸었더니 **기존 테스트가 red 로 잡았다**:
`finally { await recordApiQuota(); /* process.exit(1); */ }` 같은 **줄 중간 블록 주석**을 못 지워
주석 처리된 exit 이 "안전장치 있음"으로 오인된다(가짜 초록불 — 반대 방향 거짓).

다른 4개 형제 파일이 고정만으로 충분했던 것은 **그 케이스를 테스트로 지키지 않아서**일 뿐이다.

### ⚠️ 뮤테이션 치환을 셸 인라인으로 쓰면 역슬래시가 붕괴한다 (세션539)

`node -e` / heredoc 안에 정규식을 넣었더니 `\\s\\S` 가 `sS` 로, `\\/` 가 `/` 로 무너져
**문법 오류로 죽은 것을 "red"로 오독**할 뻔했다. 그건 "가드가 잡았다"가 아니라 "파일이 깨졌다"이다.

## ⚠️ 테스트가 **그 코드가 실제로 지나는 경로**를 지나는가 (세션 508 — 새 변종)

지금까지의 사각은 "가드가 약하다"였다. 이번 건 다르다 — **가드는 정확한데 테스트가 그 코드에
도달하지 않는다.** 순수 함수를 직접 호출하는 테스트는 그 앞단(정규화·기본값·래퍼)을 **건너뛴다.**

세션 508 실사례: `scoreLocation`/`scoreRisk` 의 null 처리를 고쳤는데, 실전 경로는 언제나
`calcCats → sanitize → scoreX` 다. `sanitize` 가 `noise` 를 75, `builderDebtRatio` 를 250 으로
**이미 굳혀서** 넘기므로 앞단을 같이 고치지 않으면 **수정이 화면에서 아무 효과가 없다.**
더 나쁜 건 그 앞단을 옛 코드로 되돌리는 뮤테이션에 **202건이 전부 초록**이었다는 점 —
단독 호출 테스트(`scoreLocation(makeApt({...}))`)가 raw 입력을 그대로 넘겨 `sanitize` 를
지나지 않기 때문이다. 즉 **그 수정이 지켜진다는 증거가 0**이었다.

### ⚠️ 재발 — 세션512에서 같은 함정이 또 났다 (룰이 있어도 안 물었다)

세션508이 위 절을 박제했는데, **세션512가 정확히 같은 실수를 반복했다.** 혜택 문구를 "미수집"으로
고치고 `scoreBenefit` 을 직접 부르는 테스트로 green 을 받았는데, `sanitize` 가 `discountPct` 를
`null → 0` 으로 눌러서 **실전 경로에서는 옛 문구 그대로**였다. 화면을 열어 보고서야 드러났다.

## ⚠️ **파생 가드는 상수 변경을 못 잡는다** — "어긋나지 않음"과 "옳음"은 다르다 (세션514)

이 저장소는 "수치를 손으로 적지 말고 **상수에서 읽어** 대조하라"를 관습으로 삼는다(세션513 파생
가드). 그런데 그 관습만 지키면 **가드 전체가 한 상수에서 파생**되므로, 그 상수를 잘못 바꿔도
문구·판정·테스트가 **함께 따라가며 전부 초록**이 된다.

실증(세션514): `LIQUIDITY_TIERS[0].min` 을 2,000 → 2,500 으로 바꾸는 뮤테이션에 **468건 전부 green**.
경계·문구·benchmark·판정이 모두 그 상수의 파생이었기 때문이다.

## ⚠️ 코더의 뮤테이션이 전부 red 여도 **가드가 0줄 늘었으면 껍데기다** (세션513)

수정한 파일마다 **테스트가 실제로 늘었는지**를 diff 로 센다. 세션513에서 코더 뮤테이션 8종이 전부
red 였는데도, 수정 파일 중 `subContext.ts`·`fieldMeta.ts` 두 곳은 테스트가 0줄 늘어 되돌려도 초록이었다
(오케스트레이터가 뒤늦게 메움). 뮤테이션 red 는 **그 뮤테이션이 겨눈 자리**만 증명한다.

## ⚠️ **이어받은 가드**는 "뮤테이션 대상" 표시가 있어도 직접 고장 내 본다 (세션523)

지금까지의 조항은 전부 **내가 새로 만든 가드**를 전제한다. 그런데 다른 세션·다른 사람이
만들어 둔 가드를 이어받는 경우가 있고, 그때 테스트 파일에 `⚠️ 뮤테이션 대상` 같은 표시가
붙어 있으면 **이미 검증됐다고 착각하기 쉽다**. 그 표시는 **의도의 표시일 뿐 실행의 증거가
아니다** — 표시를 달아 두고 실제로는 안 돌린 채 세션이 끝날 수 있다.

세션523 실사고: 직전 세션이 `lhzone-status.test.mjs` 에 그 표시를 세 곳 달아 뒀는데,
이어받아 4종을 실제로 돌려 보니 **1종이 green** 이었다 — *"포함 매칭으로 잡은 후보의 단계가
여럿이면 버린다"*(`steps.size > 1`)를 지워도 **24/24 통과**. 원인은 **같은 판정이 두 경로에
서로 다른 줄로 존재**하는데(정확 일치 경로 / 포함 경로) 테스트가 정확 일치 쪽만 지키고
있었던 것이다. 그 줄을 누가 건드리면 틀린 값이 조용히 들어갈 자리였다.

## ⚠️ 가드가 **입력 형식**을 실전과 다르게 넣으면, 경로를 지켜도 사각이 남는다 (세션529)

세션508이 "테스트가 실제 **경로**를 지나는가"를 세웠고, 세션528이 그 룰을 **명시 인용하며**
`calcCats` 경유 가드까지 만들었다. 그런데 넣은 값이 전부 `"2030-01-01"` 대시 형식이었다 —
그 형식은 **운영 DB 에 0건**이고 옛 파서가 이미 올바르게 처리하던 쪽이라, 결함 분기를 한 번도
지나지 않았다. 그 결과 준공완료 958곳을 전부 미준공으로 판정하는 결함이 가드 밑에서 살아남았다.

## ⚠️ 뮤테이션 목록에 **"경쟁 후보값"** 을 넣어라 — 옛 값만 시험하면 이번 결정은 무방비다 (세션529)

세션529는 "뮤테이션 10종 전부 red"를 근거로 들었는데, 그 10종은 전부 **앵커 범위 밖**(옛 값 복원)
이었다. 적대검증이 **앵커 범위 안의 경쟁 후보값**(그 세션이 실제로 저울질한 대안)을 넣어 보니
**둘 다 green** 이었다. 즉 가드는 "옛 값 복귀"만 막고 **이번 결정은 하나도 지키지 않았다.**

## ⚠️ 경계·범위를 **표에서 읽는 가드**는 표가 밀리면 같이 밀린다 (세션529 자책)

세션529가 "구간 인덱스가 밀리면 red" 가드를 만들면서 경계를 `band.min`/`band.max` 로 **표에서
읽었다**. 연속성을 유지한 채 경계만 미는 뮤테이션(`0~1→0~2`, `1~3→2~3`)에 **green** 이었다 —
표가 밀리자 단언도 같이 밀렸기 때문이다. **파생 가드 함정을 막으려고 쓴 가드가 그 함정에 빠졌다.**

## 차단 검증

| 사고 시나리오 | 본 룰 적용 시 |
|---|---|
| 새 감사가 정상을 오판해 CI 영구 차단 | "정상이 통과하는가" 확인에서 즉시 발견 |
| 가드를 지워도 테스트가 통과 (껍데기) | "고장이 걸리는가" 뮤테이션에서 발견 |

| 함수는 고쳤는데 앞단(sanitize)이 덮어써 **실전 효과 0** | §"테스트가 실제 경로를 지나는가" → 호출 사슬 grep + 진입점 테스트 |
| 앞단 되돌림에 테스트가 전부 초록 (증거 0) | 같은 절 → **고친 모든 줄**을 뮤테이션 대상으로 |

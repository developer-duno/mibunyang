# 파생 행을 지워 재수집을 유도할 땐 화면 재생성 시각과의 순서를 먼저 본다 — 이력 (자동 로드 안 됨)

규칙 본문은 `.claude/rules/collectors/purge-to-recollect-timing.md`. 이 파일은 그 규칙이 생긴 사건·수치·답습 자산 기록이며 세션에 자동으로 실리지 않는다.

## 사고 박제 (세션539, 2026-09-03)

소사역 프라힐스 15곳의 주소가 남의 단지 것(`소사본동 148-30`)이라 좌표가 651m 어긋나 있었다.
좌표를 고쳐도 `transport`·`schools`·`infra` 수집기는 **"이미 수집됨"을 건너뛰므로** 옛 값이 남는다.
그래서 그 45행을 지워 "미수집" 상태로 되돌렸다 — **여기까지는 옳다.**

문제는 시각이었다.

| 시각(KST) | 무슨 일 | 결과 |
|---|---|---|
| 00:20 | 좌표 정정 + 파생 45행 DELETE | DB 에 빈칸 |
| **03:09** | **`daily-deploy` 가 정적 JSON 재생성** | **빈칸이 화면에 박힘** |
| 05:33 | `collect-naver-listings-incremental` 재수집 | DB 는 정상 복구(153m·버스 19) |
| 다음날 03:00 | 다음 재생성 | 그제서야 화면 정상 |

그 사이 손님이 본 것(`ah-2024910127`, 화면 노출 1곳):

| | 고치기 전 | 지운 직후 | 원래 맞는 값 |
|---|---|---|---|
| 지하철 | 784m (틀림) | **"지하철 없음"** | 153m |
| 생활인프라 | 병원67·편의점14·공원36 | **전부 0** | 병원113·편의점18 |
| 입지 총점 | 77 | **41** | 79 |

즉 **틀린 값(-2점)을 없앤 대가로 더 틀린 값(-38점)을 하루 동안 내보냈다.**
"784m"는 그럴듯하게 틀린 값이지만 "지하철 없음·병원 0개"는 **명백한 거짓**이고 점수 타격도 훨씬 크다.

## 차단 검증

| 사고 시나리오 | 본 룰 적용 시 |
|---|---|
| 좌표·주소를 고치고 파생 행을 아무 때나 지움 | §1 두 시각 확인 → 03:20~05:00 창으로 미룸 |
| cron 시각(03:00)을 창 하한으로 씀 | §1 실측 표 → 실제 실행 03:04~03:10 → 하한 03:20 |
| 창 안이지만 그날 배포가 아직 안 끝남 | §1 `meta.json` 의 `fetchedAt` 확인(fail-close) |
| 지운 뒤 화면에 "없음"이 박힘 | §3 빈칸 표시 경로 사전 확인 → 그 필드는 안 지움 |
| DB 복구를 보고 완료 판정 | §안티패턴 → 정적 파일 재생성까지 확인 |
| 창을 놓쳐 이미 화면에 나감 | §2 `daily-deploy` 수동 트리거(사람 확인 후) |
